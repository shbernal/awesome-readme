# Animated SVG

A stylized demo is an SVG you generate from a script, animated with CSS. Use it when the scene can't be recorded, like an agent session, an MCP call or a hosted service, or when you want control over every line, color and timing.

It comes out at a few KB, stays sharp at any zoom, and ships as a light and a dark file.

The cost is that nothing ties it to the real program. If the demo has to prove real behavior, like a TUI dashboard or actual CLI output, make a [recording](recordings.md) instead.

Example: [ooxml-ai-tooling](https://github.com/shbernal/ooxml-ai-tooling), generated by [`scripts/readme-art.mjs`](https://github.com/shbernal/ooxml-ai-tooling/blob/main/scripts/readme-art.mjs). The 17-second demo is 7.5 KB.

## Why it works on GitHub

GitHub shows README images through `<img>`. Inside an `<img>`, an SVG:

- Runs CSS animations.
- Doesn't run scripts.
- Doesn't load anything external: no web fonts, no linked images, no linked stylesheets.

So keep everything in 1 file, with the animation in a `<style>` block and no JavaScript.

## Generate it

Write a plain script, Node or Python, that prints the SVG as text. No animation tool, no dependencies. Commit it next to the output.

- Hold each scene as data, a list of rows. Each row has its text pieces, a color per piece, and the second it appears.
- Keep colors in a theme object with a light and a dark palette. 1 run writes every variant, for example an animated demo, a static copy for a usage section, and each in light and dark.
- For each row, write 1 `<text>` with a `<tspan>` per colored piece, and 1 `@keyframes` rule.
- Copy the rows from real runs of the tool, then trim them. When the tool's output changes, run it again, update the rows and regenerate.

## Timeline

- Give every animation the same duration, the length of the loop, for example `17s linear infinite`. All rows then stay in step, and a row's start time is a keyframe percentage: `at / cycle * 100`.
- A row stays hidden until its time, fades in while moving up 4px, holds, and fades out near the end of the loop:

```css
@keyframes r3 {
  0%, 25.88% { opacity: 0; transform: translateY(4px) }
  27.35%, 95% { opacity: 1; transform: none }
  98.5%, 100% { opacity: 0 }
}
.r3 { animation: r3 17s linear infinite }
```

- Leave 2 to 4 seconds on the finished scene before the loop restarts.
- Loop an animation meant to play once too, like a banner that draws itself in, and hold its final frame for about 10 seconds before it replays. GitHub caches README images, so a one-shot animation runs only on a hard refresh. Readers reach the README by scrolling down past the file list, so by then it has already finished, and most never learn it moved.

## Effects

- **Typing.** Put a rectangle the color of the prompt box over the prompt text, and slide it right with `steps(n)`, where n is the number of characters. The text then appears 1 character at a time. Clip the rectangle to the prompt box with a `clipPath`. It only works on a solid background.
- **Pending tool call.** Blink the call's bullet with `steps(1)` keyframes that switch the opacity between 1 and 0.2, until its output appears.
- **Transient lines.** A line that only shows while something runs, like `running…`, rests hidden and appears only inside its keyframes.

## Fallback

Some viewers turn motion off, and some renderers ignore CSS animation. Both must still see a complete picture.

- Give every element the style of its final frame as its resting style. The keyframes hide it, the element itself doesn't. A renderer without animation then shows the finished session.
- Turn animation off for reduced motion:

```css
@media (prefers-reduced-motion: reduce) { * { animation: none !important } }
```

- Don't switch light and dark with `prefers-color-scheme` in the SVG. Ship 2 files and a `<picture>`. See [Light and dark](light-and-dark.md).

## Text

Converting text to outlines, as [Light and dark](light-and-dark.md) suggests for banners, would make a terminal scene huge. Use a monospace font stack instead:

```css
text {
  font-family: ui-monospace, SFMono-Regular, 'SF Mono', Menlo, Consolas, 'Liberation Mono', 'DejaVu Sans Mono', monospace;
  white-space: pre;
}
```

- Lay out columns at 0.6 × the font size per character. Most monospace fonts come close. Leave some room on the right, since widths vary between fonts.
- Set `xml:space="preserve"` on the root and `white-space: pre` on text. Without them, runs of spaces collapse and aligned columns fall apart.
- Escape `&`, `<`, `>` and `"` in every piece of text. 1 stray quote makes the file invalid XML, and GitHub shows a broken image.
- Give the root `role="img"` and an `aria-label`, plus a `<title>`, that say what happens in the scene. Put the same text in the `<img>` `alt`.

## Check

The animation is hard to judge at full speed, and the fallback never shows in a browser. Check both.

**Single frames.** Inline the SVG in an HTML page that pauses every animation at a chosen second, then screenshot it with headless Chromium. Every animation shares 1 cycle, so 1 negative `animation-delay` moves them all to the same moment.

```sh
t=5.6
{
  printf '<!doctype html><style>body{margin:0}*{animation-play-state:paused!important;animation-delay:-%ss!important}</style>' "$t"
  cat assets/demo-dark.svg
} > frame.html
chromium --headless --hide-scrollbars --window-size=800,520 --screenshot="$PWD/frame-$t.png" "file://$PWD/frame.html"
```

Step through the moments that matter: mid-typing, a blinking bullet, the first output row, the final frame.

**Static fallback.** Render with a tool that ignores CSS animation:

```sh
rsvg-convert assets/demo-light.svg -o static.png
```

That catches collapsed spacing, elements whose resting style is hidden, and invalid XML. rsvg-convert refuses to render a file that doesn't parse.

**On GitHub.** Push to a branch and look at the README in both themes, as in [Light and dark](light-and-dark.md).
